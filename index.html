The Local Artist Portfolio (LAP)

Next.js Supabase PostgreSQL Gemini API Vercel
Description

For my senior capstone project, I built The Local Artist Portfolio, a full-stack web application that connects local artists with their communities. Think of it as a LinkedIn and Instagram hybrid specifically for artists. Users can sign up, browse artist profiles by type and location, follow and connect with artists, send direct messages, and post to a live feed. Artists can create detailed profiles showcasing their work, style, and location. The app is built with Next.js 14, Supabase for the database and authentication, and PostgreSQL, and is deployed live on Vercel.

Reflection

This was the most technically challenging thing I have ever built. I had to figure out real-time messaging, protected routes, database schema design, AI-powered search using the Gemini API, and mobile responsiveness all at once, while learning most of it on the fly. It pushed every BCIS learning goal at the same time, from database systems to business analysis to communication, because building something real means you have to make decisions that actually matter. This project is the clearest example of what I can do when I go deep on something.

NBA Player Performance Tracker

Python Streamlit Plotly BeautifulSoup Pandas
Description

I built an interactive web application that compares NBA player statistics from the 2024-25 season against the 1995-96 season. I chose these two seasons because they represent two of the greatest individual performances in NBA history, Michael Jordan's 1996 season and Nikola Jokic's 2025 season, and I wanted to see how the game had changed. The data was scraped from Basketball-Reference HTML files using BeautifulSoup and cleaned through a six-step pipeline that handled duplicate rows, filtered out bench players, and dealt with traded players who showed up multiple times in the dataset.

Reflection

This project was one of the first times I felt like I was building something I actually wanted to use. It pushed me to think about data differently because the raw scraped data was a mess, and getting it into a usable state required real problem solving, not just following a tutorial. It also taught me how to present data in a way that makes sense to someone who just wants answers, not someone who wants to read a spreadsheet. That balance between technical work and making something accessible is something I carry into every project I build now.

Rate Radar – Landed Cost Calculator

Python Streamlit Pandas GSAP
Description

Rate Radar is a Streamlit web application that calculates the total landed cost of imported goods including freight, insurance, and import duties based on HS codes. The app has two main features: a single calculation mode where you enter an item, quantity, and unit price and get a full cost breakdown, and a country comparison mode where you can compare import costs across multiple countries side by side to find the cheapest source. The tariff data is loaded from a CSV file, the calculations follow standard customs valuation formulas, and results can be exported as CSV.

Reflection

This project pushed me into territory I hadn't worked in before. International trade and tariff calculations are not something you learn in a typical CS class, so I had to understand the actual business logic before I could code it. It also taught me how to structure a Python project properly with separate modules for models, calculations, and data loading rather than dumping everything in one file. The country comparison feature specifically made me think about how to present data in a way that actually helps someone make a decision, not just display numbers.

Utah Independent Living Center Website

Next.js TypeScript Tailwind CSS Google Calendar API
Description

As part of the LEARN team, I built a feature for the Utah Independent Living Center website, a nonprofit that provides services to people with disabilities across Utah. My contribution was replacing two outdated Google Calendar iframe embeds with a fully custom API-driven events system. I built a TypeScript fetcher that pulls upcoming events from both the Salt Lake City and Tooele office calendars, merges and sorts them by date, and caches the result for five minutes to avoid unnecessary API calls. The stack was Next.js 16, TypeScript, and Tailwind CSS.

Reflection

This project taught me what it actually means to work on a real client's codebase. I wasn't building from scratch, I was dropping into an existing system and had to understand it before touching anything. It also pushed me to think about performance, the caching layer wasn't something I was told to add, it was something I identified as necessary. Working for a nonprofit serving people with disabilities also made the work feel meaningful in a way that goes beyond just shipping code.
